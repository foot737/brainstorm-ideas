# ながさきブレスト・アイデアスキル

AIだけで発想すると、もっともらしい平均的な案に寄りがちです。このスキルでは、人間がブレストで実際に出した「評価前の生のアイデア」をヒントとして混ぜることで、発想の幅を広げます。

- データ：12テーマ・450件。各項目は `theme` / `theme_category` / `idea` / `origin` / `license`
- データのURL：https://raw.githubusercontent.com/foot737/brainstorm-ideas/main/data/brainstorm_ideas.json
- リポジトリ：https://github.com/foot737/brainstorm-ideas

## ブレストの基本ルール

このスキルを使っている間は、あなた自身もブレストの参加者としてふるまいます。

- **否定しない**：自分の案にも相手の案にも、「ただし実現は難しい」「コストがかかる」などの注釈を付けない。評価は、相手が求めたときだけ別の段階で行う。
- **量を出す**：良い案を少し出すより、多様な案をたくさん出す。
- **乗っかる**：既存のアイデアをそのまま使うのではなく、一歩ずらして新しい案にする。
- **突飛を歓迎する**：無理やりなつながりから生まれる案こそ、このスキルの価値。毎回、少なくとも1つは「笑ってしまうくらい飛んだ案」を入れる。

## 手順

### 1. テーマを受け取る

テーマがはっきりしていれば、すぐに次へ進む。曖昧な場合も、質問は1つまでにする（例：「誰向けですか？」）。答えがなくても、もっとも自然な解釈で進めてよい。

### 2. ヒントになるアイデアを取り出す

スクリプト `pick_ideas.py` を実行する。クエリには、テーマ文に加えて**言い換えや関連語を空白区切りで足す**。照合は文字の一致で行うため、同義語を足すほど関連アイデアが見つかりやすい。

**このスキルのフォルダに `scripts/pick_ideas.py` がある場合**は、それを実行する。

```bash
python3 scripts/pick_ideas.py "商店街を盛り上げたい 商店 店 街 買い物 地域 にぎわい" --seed 7
```

**ない場合**（SKILL.mdだけで使われている場合）は、スクリプトをGitHubから取得して実行する。データもスクリプトが自動でURLから読み込む。

```bash
curl -sSfL https://raw.githubusercontent.com/foot737/brainstorm-ideas/main/skill/nagasaki-brainstorm-ideas/scripts/pick_ideas.py -o pick_ideas.py
python3 pick_ideas.py "商店街を盛り上げたい 商店 店 街 買い物 地域 にぎわい" --seed 7
```

結果はJSONで返る。

| キー | 中身 | 使いみち |
|---|---|---|
| `related` | テーマに言葉が近いアイデア（最大8件） | 乗っかり |
| `random` | テーマと無関係なアイデア（6件） | 偶然の出会い |
| `pairs` | 別々のテーマから2件ずつ組にしたもの（3組） | 掛け合わせ |

`related` が少ない・空でも問題ない。その場合は `random` と `pairs` を中心に発想する。

**スクリプトを実行できない場合**（コード実行がない、ネットワークに接続できない、`error` が返った場合）：

1. Webフェッチなどで上の「データのURL」を取得できれば、その中からテーマに近いものを数件、無関係なものを数件、ランダムに近い形で選んで同じように使う。
2. それもできなければ、相手に「データのURL」からJSONファイルを保存して添付してもらうよう頼む。

### 3. 3つの発想法でアイデアを出す

合計10件前後を目安にする。

- **乗っかり**（3〜4件）：`related` のアイデアを、今回のテーマに合わせてずらす・広げる・逆にする。
- **掛け合わせ**（3件）：`pairs` の2つのアイデアと今回のテーマ、この3つを無理やり1つの案にまとめる。
- **偶然の出会い**（3件）：`random` から選んだアイデアを、テーマとは関係なくても強引にテーマへ結びつける。

各アイデアは1〜2文で、具体的な場面が浮かぶように書く。

### 4. 出力する

以下の形式で出す。ヒントは、スクリプトの出力（またはデータ）にあった文言を**そのまま**引用し、元のテーマ名を添える。

```markdown
## 「〈テーマ〉」のアイデア

### 乗っかり
1. **〈短い名前〉**：〈1〜2文の説明〉
   ヒント：「〈元のアイデア〉」（〈元のテーマ〉）

### 掛け合わせ
4. **〈短い名前〉**：〈説明〉
   ヒント：「〈アイデアA〉」×「〈アイデアB〉」

### 偶然の出会い
7. **〈短い名前〉**：〈説明〉
   ヒント：「〈元のアイデア〉」（〈元のテーマ〉）

---
ヒントの出典：ながさきキャンバス ブレストアイデア・オープンデータセット（CC0）
```

最後に、次の一手を1行で示す（例：「もっと出す」「気になった案を広げる」「絞り込む」）。

### 5. 続け方

- **「もっと」**：`--seed` を別の値に変えて再実行し、前回と違うヒントで出す。
- **「この案を広げて」**：その案を起点に、さらに乗っかり案を5件ほど出す。必要なら、その案の言葉でクエリを作り直して再実行する。
- **「絞り込みたい」**：ここで初めて評価の段階に入る。評価の基準（実現しやすさ、ワクワク度、予算など）は相手に聞いてから使う。評価の段階でも、外した案を否定的に書かない。

## やってはいけないこと

- データにないアイデアを、ヒントとして引用しない（ヒントは必ずスクリプト出力またはデータからそのまま引く）。
- データのアイデアをそのまま自分の案として出さない。必ずテーマに合わせて変形する。
- 相手が求めていないのに、案に難点・リスク・実現可能性の評価を付けない。

## 出典について

データ・このスキル・スクリプトはすべてCC0なので、出典表示の義務はありません。出力の最後に1行添えるのは、データ提供者への感謝のためです。
